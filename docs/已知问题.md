# 已知问题与开发

## 已知问题（平台侧）

- 创建任务时可能返回 `code=10205 主机不在线`：列表接口中 `status=online` 的宿主，
  其底层 taskflow 代理可能实际不可调度。这是 MonkeyCode 云平台/环境问题，非 SDK 问题。
  请在 MonkeyCode 控制台确认云端环境已真正启动，或重建一个环境后再试。
- `list_model_providers()` / `list-model-providers` 命令不可用：平台端点
  `/api/v1/users/models/providers` 对任意客户端输入（含前端自身契约
  `{api_key, base_url, provider}`、34 种参数名、GET/POST/PUT、路径变体、
  任意 model_id 值）都返回「模型ID必填（code=10300）」，平台前端「获取模型列表」
  同样失败。属平台端点自身缺陷，非 SDK 契约问题。替代方案：
  用 `list_available_models()` 或 `list-available-models` 命令，或在平台模型管理页
  手动添加模型。需平台侧修复端点后才能恢复。
- MCP 上游/工具的单价无法通过 API 枚举：平台**前端控制台在使用前**以 badge 形式
  展示单价（`docparse_parse 100 积分/次`、`imgsearch_search 5 积分/次` 等），
  后端不存在工具单价查询端点（此前探测 23 个候选路径全部 404）。
  因此 SDK/API 只能**使用后**得知实际扣费——调用后从 `wallet-tx` 的
  `amount/1000` 换算为「点」查看。`wallet-tx` 对 MCP 工具消费仅做
  「按次计费」静态提示，不硬编码具体金额（单价会变）。需平台侧提供单价端点后才能恢复。
